# Architecture decisions

1. Keep the locked Ionic Vue stack; use Vue Composition API, strict TypeScript, Pinia, SCSS and Ionic Router. No native runtime is required.
2. Use jsPDF for client PDF generation, read-excel-file for XLSX imports and write-excel-file for XLSX exports; load them only when needed. These maintained browser libraries support the approved report workflows without a backend renderer. The initial ExcelJS/pdf-lib choice was replaced during dependency review; references are in REFERENCES.md.
3. Private identities are separate from public roster records. Full student numbers never enter a general roster query.
4. Username/password authentication is mediated by an Edge Function. A server-side HMAC transforms the visible password into an Auth password, preventing direct Auth password login from bypassing the account lockout. The HMAC secret must remain stable and server-only. Username resolves to a private random internal identity; no email verification UI.
5. RLS checks active membership and an application-approved session ID. Auth tokens alone do not grant application access. Session revocation therefore takes effect without waiting for token expiry.
6. No fake backend, seeded people, or invented credentials. Unconfigured mode is an explicitly labeled preview of the shell; protected routes remain guarded.
7. Initial migrations cover identity, preferences, terms, announcements, tasks, notifications and audit foundations. Later domain migrations follow the documented inventory and permission plan, rather than prematurely granting access to unfinished workflows.
8. Cache only the static app shell in this phase. Account-scoped offline records require a separate reviewed cache lifecycle in milestone 12. No offline writes.
9. Accepted product risks remain unchanged: shared development/production Supabase project, no external backups, no Sentry, optional initial password change, immediate confirmed attachment deletion, main deploys to production, mobile installation required, desktop exception.
10. Milestone 4 persists notification choices during onboarding, ahead of milestone 10 delivery. Security notices have no user-disable preference. Policy versions and tour timestamps are assigned by database RPCs.
11. Password changes first record an operation, advance the credential generation and revoke other application sessions. The Auth update then runs, followed by an idempotent audit/security-notification transaction. Interrupted requests can be retried from the initiating session; pending changes block new logins. The administrative reset now resolves pending changes as part of its audited completion transaction.
12. Authentication tests use three distinct layers: real PostgreSQL migration/RLS execution, Deno handlers with intercepted Auth API calls, and a separately compiled Playwright contract-test build. Fixtures never enter the production build or `.env`. Real GoTrue/PostgREST verification is a separate guarded hosted pre-production command and remains a required integration gate.

13. Hosted verification uses explicit project-reference matching, one fictional student per run, a database singleton lock and service-only ownership-ledger RPCs. Cleanup retires the fixture and retains audit referents. Docker, resets and real student data are excluded. Missing hosted credentials do not block independent product implementation.
14. Account creation uses durable private reservations with caller-generated operation UUIDs, DB-enforced duplicates/capacity, service-only Auth provisioning and explicit actor audits. Other active account administrators may resume incomplete reservations. Identity reservations are retained for audit/retry safety.
15. Administrative reset revokes sessions before Auth mutation and resolves pending user changes only after a successful reset. Credential writes have bounded leases/timeouts. A private SHA-256 fingerprint of the expected HMAC credential also gates username login, so delayed Auth writes cannot revive superseded visible passwords; external divergence fails closed and is reconciled by retrying reset. Changed passwords and HMAC credentials are never stored in application tables; the required private student number remains the initial/reset password source.
16. Controlled hosted first-President provisioning uses a single private reservation and explicit project/test-target checks. Only retired fictional fixture tombstones may coexist with an otherwise empty roster. President assignment remains outside the application UI.

17. Poll creators are President/VP under the existing official-publishing capability. Poll configuration is immutable after creation; administrators can close voting early with a reason. Ballots stay in a private table; anonymous results never return identities, and voter-choice events are not copied into public audit logs. Named voting displays an explicit disclosure before submission. Result visibility rules apply to officers as well as students.
18. Task assignment snapshots the selected class/group/individual roster. Editing a task requires a reason and reapplies targeting, retaining revoked assignments and prior completion history. Group membership changes alone do not silently change existing task assignments. Completion authorization and deadline locking use database time. Reminder configuration is stored with tasks and consumed by the Milestone 10 dispatcher. Hosted delivery remains an external verification gate.
19. Group creators manage their groups. Secretary overrides are limited to membership corrections with reasons; President/VP can override metadata and archive/remove groups with reasons. Removal preserves membership/history/audits. Existing archived academic terms remain read-only.

20. Offline copies are limited to recent official announcements, own assigned tasks and own attendance summaries. They are scoped to account plus approved device session, bounded to 24 hours and removed on logout/invalidation/account change. They are a read-only local convenience, never an authorization source. Administrative datasets, file URLs and credentials are excluded. The offline page is bundled with the shell to avoid a missing lazy chunk during disconnection.
21. The private notification outbox uses expiring claims and bounded retries, validates standard push-provider destinations, rechecks preferences/session status and sends generic lock-screen content. A lost provider acknowledgment can cause a retry; stable notification tags mitigate duplicate display. Hosted/provider validation remains required.
22. Reports use a single authorized, audited server snapshot before local PDF/Excel generation. Search executes under invoker RLS, and analytics exposes only aggregate private-ballot counts to President/VP. Problem reporting captures no automatic form contents or screenshots.
